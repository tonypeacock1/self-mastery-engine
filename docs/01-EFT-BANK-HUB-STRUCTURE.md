# 01 — Clean EFT Bank Hub + Order-Ref Structure

**Status:** Isolated · placeholders only · never commit live account numbers  
**Aligned with:** Proven SA Instant EFT pattern from the existing book-fulfillment site

---

## Customer flow (same proven pattern)

1. Customer submits order form on the mini-site / landing page  
2. Frontend (or Worker) generates unique **orderRef**: `SM-XXXXXXXX`  
3. `POST /api/resolve-eft` returns the regional bank details for their city/suburb  
4. Customer is shown:

   | Field            | Example (placeholder)              |
   |------------------|------------------------------------|
   | Bank             | First National Bank (FNB)          |
   | Account Name     | Gauteng Self-Mastery Publications  |
   | Account Number   | *(from vault — never in git)*      |
   | Branch Code      | 250655                             |
   | Amount           | **R400.00**                        |
   | **Reference**    | **SM-A7K2M9QX** ← must use this    |

5. Customer Instant-EFTs using that reference  
6. Operator (or bank API) confirms → `POST /api/process-order` (or payment-confirmed webhook)  
7. Dispatch alert email + CRM lead + shipping notification

---

## Order reference format

```
SM-XXXXXXXX
```

- Prefix `SM` = Self-Mastery (non-trademark)  
- 6–12 alphanumeric characters (no ambiguous 0/O/1/I)  
- Regex enforced in Worker: `/^SM-[A-Z0-9]{6,12}$/`  
- Generated by `generateOrderRef()` in `dianetics_vault_config.ts`

This mirrors the proven `ORD-XXXXXXXX` pattern, rebranded for isolation.

## Worker endpoints

| Method | Path                  | Purpose                                      |
|--------|-----------------------|----------------------------------------------|
| POST   | `/api/resolve-eft`    | Geo-IP / city → bank details + R400 + ref hint |
| POST   | `/api/process-order`  | Validate orderRef, SendGrid dispatch alert, CRM |

CORS is restricted; responses are no-store.
